# 한국어 문장 규칙

슬라이드 문장은 사람이 설명하듯 쓴다. 규칙은 신호다. lint가 잡는 것은 일부이고, 나머지는 소리 내어 읽어 보고 판단한다. 금지어를 피하려고 같은 뜻의 다른 상투구로 바꾸지 않는다. 문장 자체를 다시 쓴다.

표의 `검사` 칸: **오류**는 lint가 실패시키고, **경고**는 사람이 판단하고, **검토**는 lint가 보지 못한다.

## 말투

| 규칙 | 나쁜 예 → 좋은 예 | 검사 |
|---|---|---|
| 본문, 정리, 노트는 "~다" 평서문으로 쓰고 합니다체와 해요체를 섞지 않는다 | "VACUUM이 dead tuple을 정리합니다." → "VACUUM이 dead tuple을 정리한다." | 오류 `speech-level` |
| 제목은 내용을 담은 문장이나 명사구로 쓰고 마침표를 찍지 않는다 | "인덱스 알아보기." → "B-tree 리프는 키 순서로 정렬되고 옆 리프와 이어진다" | 오류 `title-period`, 경고 `style` |
| 부제는 제목을 되풀이하지 않고 독자가 볼 것을 말한다 | 제목 "HOT 업데이트" / 부제 "HOT 업데이트를 알아본다" → 부제 "같은 페이지에 새 버전을 두면 인덱스를 고치지 않는다" | 검토 |
| 예고하지 말고 바로 설명한다 | "다음과 같이 살펴보자" → 내용을 바로 쓴다 | 경고 `style` |

## 문장

| 규칙 | 나쁜 예 → 좋은 예 | 검사 |
|---|---|---|
| 대시(—, –)를 쓰지 않는다. 나열은 `·`, 범위는 `~`, 흐름은 `→`, 나머지는 문장을 나눈다 | "원인 — 잠금 대기" → "원인은 잠금 대기다" | 오류 `dash` |
| 연결어미 뒤에 쉼표를 찍지 않는다 | "요청이 오고, 워커가 처리한다" → "요청이 오고 워커가 처리한다" | 오류 `connective-comma` (설정으로 끌 수 있다) |
| 명사를 쌓지 말고 동사로 쓴다 | "요청에 대한 검증을 수행한다" → "요청을 검증한다" | 경고 `style` |
| ~에 대한, ~을 통해, ~에 있어, ~에 의해는 풀 수 있으면 푼다 | "워커에 의해 처리된다" → "워커가 처리한다" | 경고 `style` |
| "~하는 것이다"로 끝내지 않는다 | "원인은 락을 오래 잡는 것이다" → "락을 오래 잡아서 느려졌다" | 경고 `style` |
| 가능성을 겹쳐 쓰지 않는다 | "발생할 가능성이 있을 수 있다" → "발생할 수 있다" | 오류 `banned` |
| "A가 아니라 B" 모양을 한 장에 두 번 넘게 쓰지 않는다 | 카드마다 "~가 아니라 ~다" → 한 곳만 남기고 나머지는 사실만 쓴다 | 경고 `contrast-cadence` |
| 지시어가 가리키는 대상이 멀면 명사를 다시 쓴다 | 카드 첫머리 "이를 통해" → "이 인덱스로" | 경고 `style` |
| 같은 문장 모양을 장마다 되풀이하지 않는다 | 모든 정리가 "핵심은 ~다" | 경고 `style`, 검토 |

## 어휘

| 규칙 | 나쁜 예 → 좋은 예 | 검사 |
|---|---|---|
| 비유와 극적 표현 대신 실제 동작을 쓴다 | "쿼리가 디스크를 태운다", "청구서가 날아온다" → "쿼리가 페이지 수만 장을 읽는다" | 경고 `style` |
| 사물을 사람처럼 쓰지 않는다 | "인덱스가 플래너에게 약속한다" → "플래너는 이 인덱스로 정렬을 건너뛴다" | 경고 `style` |
| 과장어와 평가어 대신 무엇이 달라졌는지 쓴다 | "획기적으로 개선" → "읽는 페이지가 크게 줄었다" | 경고 `style` |
| 번역한 새 말보다 개발자가 실제로 쓰는 말을 쓴다 | 청소 → VACUUM, 죽은 행 → dead tuple, 표(DB) → 테이블 | `replace`로 설정 |
| 식별자, 설정 이름, 상태 값은 원래 표기로 둔다 | "공유 버퍼 설정" → `shared_buffers` | 검토 |
| 제품과 기술 이름은 공식 표기를 따른다 | Postgresql, mysql → PostgreSQL, MySQL | `replace`로 설정 |
| 한 개념에는 한 이름만 쓴다 | 한 자료 안에 리팩토링과 리팩터링 | 경고 `variants` |
| 한 동작에도 한 표현만 쓴다 | "visibility map이 선다"와 "비트가 켜진다"를 섞어 쓰기 → "비트가 켜진다"로 통일 | 둘 다 `variants`에 등록 |
| 본문의 "N장"은 이 자료의 장만 가리킨다 | "12장은 원인을 …에서 찾는다"(바깥 문서 12장) → "원인은 …로 본다 ({{#c4-visibility-map}}장)", "리프까지 3~4장" → "3~4페이지" | 검토. 장 번호는 `{{#id}}`로만 쓴다 |
| "덱"이라고 쓰지 않는다 | "이 덱은" → "이 자료는" | 오류 `banned` |
| "상한"은 풀어 쓴다 | "상한이 없다" → "제한 시간이 없다", "최대 횟수가 없다" | 경고 `style` |
| 이모지를 쓰지 않는다 | | 오류 `emoji` |

## 숫자

| 규칙 | 예 | 검사 |
|---|---|---|
| 이해를 돕는 숫자만 남긴다 | "400,213개 → 3,871개" → "읽는 페이지가 백분의 일 아래로 줄었다" (자세한 값은 근거 목록에) | 경고 `numbers` |
| 크기를 가늠하게 하는 어림값은 괜찮다 | "약 300MB, 3초" | |
| 숫자와 단위는 한 덩어리로 둔다 | "203" 과 "MB"를 다른 요소에 두지 않는다 | 검토 |
| 시각에는 기준 시간대를 붙인다 | "14:05" → "14:05 KST" | 경고 `timezone` (켜면) |
| 예제와 실측을 구분한다 | 계산 예제 그래프에 "예제" 표시 | 검토 |

## 사실과 확신

- 근거로 확인할 수 없는 서술을 쓰지 않는다. "팀이 몰랐다" 대신 "이 문제를 풀려면 이 개념이 필요했다"고 쓴다.
- 확인하지 못한 것은 확인하지 못했다고 쓴다. 추정은 추정이라고 쓴다.
- 없는 경험이나 감정을 지어내지 않는다.

## 스스로 점검하기

한 장을 다 쓰면 정리 한 문장만 읽어 본다. 그 문장이 장의 내용을 대표하지 못하면 장을 다시 짠다. 그다음 본문을 소리 내어 읽는다. 숨이 차거나 같은 끝맺음이 세 번 이어지면 고친다.
