## 감사 뒤 바꾼 것

- 감사 1차: Index Scan이 테이블 페이지도 읽는다는 개념이 빠졌다는 지적을 받아 5장 카드로 넣고, 8장에 Buffers를 테이블과 인덱스로 나눈 막대를 더했다.
- 감사 2차: 고친 쿼리의 실행 계획이 어디에도 없다는 지적을 받아 5장에 계획 발췌를 넣었다. 8장 제목과 막대를 페이지 수가 아니라 Buffers 기준으로 바꿨다.
- 감사 3차: 2차에서 5장(원리)에 넣은 고친 쿼리의 계획과 Buffers 102가 해결 단계보다 먼저 나온다는 지적을 받았다. 계획 발췌, Index Cond, Index Searches, 102의 구성을 8장으로 옮기고 5장은 트리와 범위 읽기, TID로 테이블을 읽는 것만 남겼다. 7장이 변동성과 표현식 인덱스를 함께 가르친다는 지적에 따라 표현식 인덱스를 새 9장으로 옮겨 10장이 됐다. 해결 단계에 고친 계획 읽기와 대안 비교가 함께 들어가면 한 장이 세 가지를 가르치게 되어 나눴다. 테이블 접근이 72번인 이유(행이 시간 순서로 모여 있음)와 hit·read와 테이블·인덱스가 다른 기준이라는 것은 실험 08~10으로 확인해 8장에 넣었다.
- 확인 감사: 5장과 10장의 Index Scan 설명을 "옆으로 읽으며 TID로 행을 가져오고 끝 키에서 멈춘다"는 순서로 맞췄다. 8장 섞은 사본 막대에 Index Scan을 강제한 값이라고 적고 플래너가 고른 계획을 더했다(C42). 3장 노트에 병렬 계획을 설명했다.
- 확인 감사 2차: 5장 번호를 읽는 순서대로 바꾸고, 6장 시각에 KST를 붙였다. 8장 코드 강조에 Index Scan 줄을 넣고 카드에 "이어지는 TID"라고 썼다. 3·5·9장의 빈 공간을 줄였다. 8장 밀도는 결정 기록대로 두었다.
