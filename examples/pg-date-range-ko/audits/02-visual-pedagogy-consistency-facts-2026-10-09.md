## 2. 새 결함 (심한 것부터)

1. **(중간) 8장 밀도가 그대로이고 lint 무시 사유가 경고 내용과 다르다.**
   - density 경고 원문은 "slides 8, 9, 10 are dense in a row"다. 무시 사유는 10장(마무리 표)만 설명하고, README도 이것을 "10장 밀도 경고"로 적는다.
   - 8장은 여전히 네 가지를 한 장에서 가르친다. 고친 계획과 Index Cond·Index Searches, Buffers 감소, 102의 두 가지 나눔, 테이블 접근 72번의 이유와 섞은 사본이다.
   - 이는 brief 결정 기록의 "한 장이 한 가지만 가르치게"와 어긋난다.
   - 고치는 길은 둘이다. 섞은 사본 비교(카드 뒷문장과 막대)를 빼서 10장 "직접 해 보기"로 넘기거나, 유지 결정을 brief에 적고 무시 사유를 8·9장까지 넓힌다.
2. **(중간) plan.md 5장 요지가 N1 이전 문장 그대로다.**
   - 문장은 "리프를 옆으로 읽다가 끝 키에서 멈추고 TID로 테이블 행을 가져온다"이다. 공개 폴더 안에서 슬라이드와 반대 순서를 말한다.
   - 같은 표의 8장 근거 칸에는 C4와 C42가 없다.
   - "감사 뒤 바꾼 것"에도 확인 감사 반영 내용이 없다.
3. **(낮음) 8장 카드의 "TID가 대부분 다른 페이지를 가리킨다"에 "이어지는"이 빠졌다.**
   - 사본에서 7월 1일 9,600행은 5,382페이지에 있다(페이지당 약 1.8행). 글자 그대로 읽으면 맞지 않는다.
   - 9,598이 5,382보다 큰 것은 4장 "같은 페이지에 두 번 접근하면 두 번 센다"의 실제 예인데 두 장을 잇는 말이 없다.
4. **(낮음) 8장 코드 강조에서 "-> Index Scan using …" 줄이 빠졌다.**
   - 강조는 Index Cond~Buffers 세 줄뿐이다.
   - 3장은 "-> Seq Scan" 줄부터 강조한다. 두 장이 대비하는 노드 이름(Seq Scan과 Index Scan)이 강조에서 빠진다.
5. **(낮음) README 검증 기록이 실제와 다르다.**
   - "네 차례 검토했습니다. 보고서는 audits/에 있습니다"라고 하지만 audits/에는 보고서가 1건뿐이다. 앞선 감사는 review.json에 요약만 있다.
   - "마지막 감사 지적을 고친 뒤의 빌드는 다른 에이전트가 다시 보지 않았습니다"는 이번 감사 뒤에 고쳐야 한다.
6. **(낮음, 시각) 빈 공간이 한쪽에 쏠린다.**
   - 3장: 노트와 흐름 상자 사이에 65px쯤 빈 띠가 있다. 다른 간격은 14~24px다.
   - 9장: 아래 두 선택 카드는 본문이 두 줄인데 높이가 190px쯤이라 절반이 빈다. 위쪽(흐름, 코드, 막대, 노트)은 빽빽하다.
   - 5장 오른쪽 카드도 같은 문제다(1절).
7. **(낮음, 문장) 6장 시각 칸에 시간대가 없다.**
   - "06-30 22시" 같은 칸이 writing-ko.md의 "시각에는 기준 시간대를 붙인다"에 어긋난다.
   - 행 머리나 구간 라벨에 "(KST)"를 한 번만 붙여도 된다.
