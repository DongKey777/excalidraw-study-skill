# 하루치 주문 조회로 배우는 B-tree 범위 스캔

excalidraw-study 스킬로 만든 공개 예제입니다.\
날짜 조건에 함수를 씌운 쿼리 하나를 사건 순서로 따라갑니다.\
실행 계획, Buffers, B-tree 범위 스캔, 함수의 변동성을 다룹니다.

실제 서비스에서 일어난 일이 아니라 로컬 PostgreSQL 18.6에서 재현한 예제 상황입니다.

## 여는 법

- 합본: `pg-date-range.excalidraw`
- 낱장: `build/slides/NN-id.excalidraw`
- 미리보기: `build/render/NN-id.png`
- 전체 보기: `build/render/contact-01.png`

합본은 excalidraw.com이나 VS Code·Obsidian의 Excalidraw 확장에서 열 수 있습니다.

## 구성

| 장 | 단계 | 제목 |
|---|---|---|
| 1 | 표지 | 하루치 주문 조회로 배우는 B-tree 범위 스캔 |
| 2 | 상황 | 하루치 주문 금액을 더하는 쿼리가 테이블 전체를 읽었다 |
| 3 | 분석 | 실행 계획에 Seq Scan과 Filter가 찍혔다 |
| 4 | 원리 | Buffers는 쿼리가 페이지에 접근한 횟수를 센다 |
| 5 | 원리 | B-tree 리프는 키 순서로 정렬되고 옆 리프와 이어진다 |
| 6 | 원리 | 조건에 쓴 식이 인덱스에 저장한 식과 달라서 인덱스를 못 썼다 |
| 7 | 원리 | date(timestamptz)는 세션 시간대에 따라 결과가 달라진다 |
| 8 | 해결 | 날짜 조건을 반열린 범위로 바꾸자 Buffers가 7,353에서 102로 줄었다 |
| 9 | 해결 | 시간대를 적은 날짜 식으로는 표현식 인덱스를 만들 수 있다 |
| 10 | 마무리 | 이제 설명할 수 있는 것 |

슬라이드 제목과 본문은 학습 자료의 기본 말투인 "~다"로 썼습니다.

## 검증 기록

자동 검사 결과 오류와 경고는 없습니다.\
이유를 적고 넘긴 경고가 두 건 있습니다(`build/lint.json`).

- 6장: 정렬된 키 값 자체가 그림이라 숫자 개수 경고를 넘겼습니다.
- 10장: 앞 장의 질문과 답을 모은 표라 밀도 경고를 넘겼습니다.

렌더링한 10장은 모두 원래 크기로 확인했습니다.\
확인한 장은 PNG 해시와 함께 `review.json`에 남아 있습니다.

슬라이드를 만들지 않은 에이전트가 사실, 설명 순서, 문장, 그림을 네 차례 검토했습니다.\
보고서는 `audits/`에 있습니다.

- 숫자는 매번 실험 출력과 맞았습니다.
- 크게 고친 것은 설명 순서, 7장의 범위, Index Scan이 테이블 행을 가져오는 순서였습니다.

확인하지 못한 것도 있습니다.

- 마지막 감사 지적을 고친 뒤의 빌드는 다른 에이전트가 다시 보지 않았습니다.
- 실행 시간은 한 번 잰 값이라 하드웨어에 따라 다를 수 있습니다.
