# 하루치 주문 조회로 배우는 B-tree 범위 스캔

excalidraw-study 스킬로 만든 공개 예제다. 날짜 조건에 함수를 씌운 쿼리 하나를 사건 순서로 따라가며 실행 계획, Buffers, B-tree 범위 스캔, 함수의 변동성을 배운다. 실제 서비스의 사건이 아니라 로컬 PostgreSQL 18.6에서 재현한 예제 상황이다.

## 여는 법

- 합본: `pg-date-range.excalidraw`를 excalidraw.com, VS Code Excalidraw 확장, Obsidian Excalidraw 플러그인에서 연다.
- 낱장: `build/slides/NN-id.excalidraw`
- 미리보기: `build/render/NN-id.png`, 전체 보기 `build/render/contact-01.png`

## 구성

| # | 단계 | 제목 | 배우는 것 |
|---|---|---|---|
| 1 |  | 하루치 주문 조회로 배우는 B-tree 범위 스캔 | 목차 |
| 2 | 상황 | 하루치 주문 금액을 더하는 쿼리가 테이블 전체를 읽었다 | 필요한 행과 읽은 페이지의 차이, 8kB 페이지 |
| 3 | 분석 | 실행 계획에 Seq Scan과 Filter가 찍혔다 | EXPLAIN ANALYZE, Seq Scan, Filter, Buffers, 실험 조건(시간대, 병렬 끔) |
| 4 | 원리 | Buffers는 쿼리가 페이지에 접근한 횟수를 센다 | shared hit와 read |
| 5 | 원리 | B-tree 리프는 키 순서로 정렬되고 옆 리프와 이어진다 | 리프, TID, Index Scan이 범위를 읽고 테이블 행을 가져오는 순서 |
| 6 | 원리 | 조건에 쓴 식이 인덱스에 저장한 식과 달라서 인덱스를 못 썼다 | 조건에 쓴 식과 인덱스에 저장한 식, 반열린 범위 |
| 7 | 원리 | date(timestamptz)는 세션 시간대에 따라 결과가 달라진다 | timestamptz, STABLE과 IMMUTABLE, `::date` 형 변환 |
| 8 | 해결 | 날짜 조건을 반열린 범위로 바꾸자 Buffers가 7,353에서 102로 줄었다 | 고친 쿼리의 계획, Index Cond, Index Searches, 102의 구성, 테이블 접근이 적은 이유 |
| 9 | 해결 | 시간대를 적은 날짜 식으로는 표현식 인덱스를 만들 수 있다 | AT TIME ZONE과 timestamp, 표현식 인덱스, 두 방법의 비용 |
| 10 |  | 이제 설명할 수 있는 것 | 질문과 답 |

## 검증 기록

- 자동 검사: 오류와 경고는 없다. 이유를 적어 넘긴 경고가 두 건 있다(`build/lint.json`).
  - 6장: 정렬된 키 값이 그림의 내용이라 숫자 개수 경고를 넘겼다.
  - 10장: 앞 장의 질문과 답을 모은 표라 밀도 경고를 넘겼다.
- 렌더 검토: Excalidraw 0.18.1로 렌더링한 10장을 모두 원래 크기로 봤다. 본 장은 `review.json`에 PNG 해시와 함께 남겼다.
- 감사: 슬라이드를 만들지 않은 에이전트가 사실, 설명 순서, 문장, 그림을 네 차례 검토했다. 보고서는 `audits/`, 기록은 `review.json`에 있다.
  - 숫자는 매번 실험 출력과 맞았다. 일회용 컨테이너에서 실험을 다시 돌려도 같은 값이 나왔다.
  - 고친 것 가운데 큰 것은 세 가지다. 원리 장에서 해결 장의 결과를 먼저 보여 주던 순서, 한 장에서 두 가지를 가르치던 7장, Index Scan이 테이블 행을 가져오는 순서 설명이다.
- 확인하지 못한 것
  - 마지막 감사 지적을 고친 뒤의 빌드는 다른 에이전트가 다시 보지 않았다.
  - 실행 시간은 한 번 잰 참고값이다. 다른 하드웨어에서는 다를 수 있다.
